## Context

当前 demo.html 中 GIF 导出的关键参数全部硬编码：
- 帧率固定 8fps，帧时间间隔 `t = trimStart + i/8`
- 输出宽度固定 480px，gif.js quality 固定 10
- 选段上限 `Math.min(3, videoDuration)`，无源视频时长限制
- 无倍速概念，帧提取严格按源视频时间轴 1:1

需要在现有 HTML+JS 单文件架构内，以最小侵入方式加入倍速、画质、时长三个控制维度。

## Goals / Non-Goals

**Goals:**
- 用户可在裁剪界面选择倍速（5 档），影响帧提取的时间间隔
- 用户可选择画质档位（3 档），影响输出分辨率和编码质量
- 源视频不超过 30s，选段不超过 10s，帧数不超过 60
- 照片模式也同样受画质档位影响

**Non-Goals:**
- 不增加新页面/新步骤，所有控制在现有界面内完成
- 不修改 gif.js 库本身
- 不引入新依赖

## Decisions

### 1. 倍速实现：修改帧时间间隔

```
当前:  t = trimStart + i/8        // 每帧 125ms 间隔
加速:  t = trimStart + i/(8 * speed)  // speed>1 时实际截取更长的源片段
放慢:  t = trimStart + i/(8 * speed)  // speed<1 时帧间间隔更密
```

备选方案"复制帧"被否决——放慢时复制帧导致画面卡顿，不如提取更密的源帧（前提是源视频选段够长）。

倍速与选段、帧数的联动：
```
实际需要截取的源视频长度 = 输出帧数 / (8 * speed)
例：60 帧 / (8 * 0.25) = 30s → 源视频必须 ≥ 30s
```

### 2. 画质档位映射

| 档位 | state 值 | 宽度 | gif.js quality | 照片宽度 |
|------|---------|------|---------------|---------|
| 流畅 | `'low'` | 360 | 20 | 360 |
| 标准 | `'medium'` | 480 | 10 | 480 |
| 高清 | `'high'` | 640 | 3  | 640 |

quality 数值越大画质越低（gif.js 采样间隔，反比关系），高清用 3 而非 1 是为了防止文件超过 2MB。

### 3. UI 布局

Step 1 裁剪界面现有：时间标签 → trim-track 滑块 → 预览按钮。倍速选择器放在滑块下方，画质选择放在 Step 3 导出区。

```
Step 1（裁剪）:
  [预览区]
  起始: Xs  时长: Xs  结束: Xs    ← 时间标签
  [=========|========]              ← trim-track 滑块
  倍速: [1/4] [1/2] [原速] [1.5] [2]  ← 新增

Step 3（预览导出）:
  画质: [流畅] [标准●] [高清]         ← 新增
  帧数预计: 24 帧 / 约 300KB         ← 新增动态预估
  [导出 GIF]
```

### 4. State 扩展

```javascript
state.speed = 1;           // 倍速：0.25 | 0.5 | 1 | 1.5 | 2
state.qualityLevel = 'medium'; // 'low' | 'medium' | 'high'
state.maxFrames = 60;       // 最大帧数上限
```

## Risks / Trade-offs

- [Risk] 用户选 10s 片段 + 0.25x 倍速 → 理论帧数 320 帧 → 被 60 帧截断
  → Mitigation: 导出预览区实时显示"预计 XX 帧 / XX 帧有效"，超出时红色提示被截断
- [Risk] 高清档 60 帧可能超 2MB → 微信发送有大小限制
  → Mitigation: 导出完成后显示文件大小，用户可自行判断
- [Risk] 0.25x 放慢需要提取更密的帧，seek 精度可能不足
  → Mitigation: 实际帧间隔 = 1/(8*0.25) = 500ms，远大于 seek 精度，无问题
